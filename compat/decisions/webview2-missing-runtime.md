# WebView2 missing runtime: detection, missing-runtime state and user-initiated install

Status: **proposed — requires Task 8 approval**

Scope: `crates/marknexia-webview` (`bootstrap.rs`, `bootstrap_native.rs`, `environment.rs` detection) and `crates/marknexia-win32` (`window/runtime.rs` and its `runtime:` hooks in `window.rs`). The distribution contract is `packaging/webview/README.md`. The .NET source is `src/Marknexia.App/MainWindow.xaml.cs` (`GetOrCreateWebViewEnvironmentAsync`, `PrepareWebViewAsync`, and the `catch` blocks that call `ShowDiagnostic`).

Evidence class: implemented, compiled and headless-tested (`crates/marknexia-webview/tests/bootstrap.rs`, 32 tests, in-memory fakes only). The loader override that the native gate relies on was native-tested on x64: `native_loader_reports_missing_for_a_nonexistent_browser_folder` passed (a child process with `WEBVIEW2_BROWSER_EXECUTABLE_FOLDER` set to a missing folder reads `RuntimeStatus::Missing`). The native shell gate `crates/marknexia-win32/tests/native_runtime.rs` has not run yet (the workstation was locked). The real download, the Authenticode check of the real bootstrapper and the real install have not run: no test may download or run the bootstrapper, so they need a manual run on a clean VM (Phase 5 exit). ARM64 is not tested.

## .NET behavior (read from the source, not observed)

The .NET app has no runtime detection and no install path. `CoreWebView2Environment.CreateWithOptionsAsync` runs when the first document opens (`PrepareWebViewAsync`). Without a runtime it throws (*unverified*: `WebView2RuntimeNotFoundException`); the open path's `catch (Exception ex)` shows `Unable to open document: <exception message>` as an error in the diagnostics bar. There is no link to an installer. What the welcome view shows without a runtime is *unverified*.

| WV2-1 | Detection | None until the first document opens; then the environment creation exception. | At startup, after the window is shown, `GetAvailableCoreWebView2BrowserVersionString` with the default browser folder. A null or empty version, `0x80070002`, or a preview channel (`beta`, `dev`, `canary`) is a missing runtime. Any other loader error keeps the earlier behavior (the session start reports it). |

| WV2-3 | Install action | None. | A push button `Install WebView2 Runtime` (AutomationId 2031) and a link `Get Microsoft's offline installer` (SysLink, AutomationId 2033; a push button without Common Controls 6) that opens `https://developer.microsoft.com/microsoft-edge/webview2/` in the default browser. Nothing downloads or runs before the button is pressed. |
| WV2-4 | Online install | Not applicable. | On a worker thread: WinHTTP GET of `https://go.microsoft.com/fwlink/p/?LinkId=2124703` with the system proxy, TLS 1.2 or later, redirects followed by hand (at most 5, each HTTPS on port 443 to `microsoft.com` or a subdomain, no user information), resolve and connect timeouts of 15 s, send and receive timeouts of 30 s, a 300 s overall limit, and a body bound of 8 MiB (a larger `Content-Length` is refused before reading; a short body is refused). Bytes outside 64 KiB to 8 MiB, or not starting with `MZ`, are rejected before anything is written. The file is written to a new folder `%TEMP%\Marknexia-WebView2-<random>` as `MicrosoftEdgeWebview2Setup.exe` (create-new, never overwritten) and held open with read-only sharing until it is deleted. `WinVerifyTrust` (generic verify v2, no UI, whole-chain revocation, MD2/MD4 disabled) must succeed, the leaf certificate name must be `Microsoft Corporation` and the chain root a `Microsoft Root Certificate Authority`. Then `CreateProcessW` runs `"<file>" /install` without elevation (no `runas`; the bootstrapper's own window shows progress) and waits up to 15 minutes. The file and folder are deleted, and detection runs once. |
| WV2-5 | Progress | Not applicable. | The document area shows the step: downloading, checking the signature, installing (`Follow the steps in the installer window.`), checking for the runtime. A `Cancel download` button is shown while an attempt runs and is enabled until the installer starts; after that the installer's own window offers cancel. |
| WV2-6 | Offline, failed download, failed signature, cancellation, failed install | Not applicable. | The shell stays usable. The document area and the diagnostics bar show the reason (warning for a cancellation, error otherwise), the offline installer link stays visible, and the install button stays available for another explicit attempt. Nothing retries automatically. A rejected signature never runs the file. An installer that needs elevation (`ERROR_ELEVATION_REQUIRED`) is not elevated; the message points to the offline installer. An installer that is still running after 15 minutes is left running. |
| WV2-7 | Runtime found after the install (also after a non-zero installer exit code) | Not applicable. | The WebView session starts in the running shell; open document tabs render again from their paths, welcome tabs get their placeholders, and the diagnostics bar shows `WebView2 Runtime <version> is installed.` If detection still finds no runtime, the message says so and suggests a restart or the offline installer. |
| WV2-8 | Startup readiness events (`Local\Marknexia.StartupFailed.<pid>`) | Not applicable. | Signalled at once when the runtime is missing, as for any WebView2 start failure. |
| WV2-9 | Test override | Not applicable. | The loader's own `WEBVIEW2_BROWSER_EXECUTABLE_FOLDER` is honored (no new Marknexia variable); the native gate points it at a missing folder. The shell test support removes an inherited value for every other launch. |

## Security notes

* Trust comes only from the Authenticode check of the locked file; the URL allow-list and the `MZ` check limit what reaches the disk but are not trust decisions.
* The download, staging and installer run never happen without the button press; the worker's results are applied on the UI thread from the message-loop tail.
* No elevation is requested, no system setting is changed, and nothing is added to the system or user configuration by Marknexia. The bootstrapper itself installs the runtime per user (or per machine when it is run elevated by the user outside Marknexia).

## Rollback

Remove the `runtime:` hooks in `window.rs`; the shell then starts a session that fails as before. The staged folder is deleted after each attempt; a crash during an attempt can leave one `%TEMP%\Marknexia-WebView2-*` folder.
