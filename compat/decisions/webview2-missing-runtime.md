# WebView2 missing runtime: detection, missing-runtime state and user-initiated install

Status: **approved — owner decision 2026-11-06 (G0)**

Scope: `crates/marknexia-webview` (`bootstrap.rs`, `bootstrap_native.rs`, `environment.rs` detection) and `crates/marknexia-win32` (`window/runtime.rs` and its `runtime:` hooks in `window.rs`). The distribution contract is `packaging/webview/README.md`. The .NET source is `src/Marknexia.App/MainWindow.xaml.cs` (`GetOrCreateWebViewEnvironmentAsync`, `PrepareWebViewAsync`, and the `catch` blocks that call `ShowDiagnostic`).

Evidence class: implemented, compiled and headless-tested (`crates/marknexia-webview/tests/bootstrap.rs`, 39 tests, in-memory fakes only; the owner-only staging DACL is checked on a real empty folder). The loader override that the native gate relies on was native-tested on x64: `native_loader_reports_missing_for_a_nonexistent_browser_folder` passed (a child process with `WEBVIEW2_BROWSER_EXECUTABLE_FOLDER` set to a missing folder reads `RuntimeStatus::Missing`). The native shell gate `crates/marknexia-win32/tests/native_runtime.rs` (gate `uia-native-runtime` in `scripts/Test-RustNativeGates.ps1`, 1 attempt) has not run yet (the workstation was locked). The real download, the redirect chain, the Authenticode and chain-policy checks and the version resource of the real bootstrapper, and the real install have not run: no test may download or run the bootstrapper, so they need a manual run on a clean VM (Phase 5 exit). ARM64 is not tested.

## .NET behavior (read from the source, not observed)

The .NET app has no runtime detection and no install path. `CoreWebView2Environment.CreateWithOptionsAsync` runs when the first document opens (`PrepareWebViewAsync`). Without a runtime it throws (*unverified*: `WebView2RuntimeNotFoundException`); the open path's `catch (Exception ex)` shows `Unable to open document: <exception message>` as an error in the diagnostics bar. There is no link to an installer. What the welcome view shows without a runtime is *unverified*.

The file and folder are deleted, and detection runs once. |

## Security notes

* Trust comes from the Authenticode check of the locked file (WinVerifyTrust, the Microsoft root chain policy, the code-signing usage and the signer names); the host allowlist, the `MZ` check and the version resource limit what reaches the disk or runs but are not trust decisions on their own.
* Revocation fails open when offline: with `WTD_REVOKE_WHOLECHAIN`, `WinVerifyTrust` accepts a chain whose revocation status cannot be retrieved (the standard Authenticode default). This is kept deliberately; a download that succeeded implies connectivity, and the chain policy and names still apply.
* Command and notification sources are checked: a `WM_COMMAND` or `WM_NOTIFY` acts only when its source window is the install button, the cancel button or the link.
* The download, staging and installer run never happen without the button press; the worker's results are applied on the UI thread from the message-loop tail.
* No elevation is requested, no system setting is changed, and nothing is added to the system or user configuration by Marknexia. The bootstrapper itself installs the runtime per user (or per machine when it is run elevated by the user outside Marknexia).

## Rollback

Remove the `runtime:` hooks in `window.rs`; the shell then starts a session that fails as before. The staged folder is deleted after each attempt; a crash during an attempt, or a standard user's still-running installer at timeout or shutdown, can leave one `%TEMP%\Marknexia-WebView2-*` folder.
