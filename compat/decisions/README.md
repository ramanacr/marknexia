# Intentional target-only decisions

These decisions are deliberately outside the frozen .NET baseline and must not alter a v1 expected result. Status: **proposed for feasibility review; not yet approved for implementation.** The Task 8 go/no-go decision is the approval authority.

* **Package manifest validation — proposed.** The Rust package manifest may replace the current installer’s `.dll` and `.pri` payload-file checks with equivalent Rust artifact and resource-manifest validation, while retaining archive traversal, required-payload, size-limit, and checksum protections. Rationale: file names are implementation-specific, while those protections are compatibility and security contracts.
* **Settings backup and migration — proposed.** The Rust settings store may use atomic backup and migration semantics. The .NET baseline records the current fail-soft load, normalization, recent-item bounds, and atomic temporary-file replacement behavior; a target migration must preserve those user-visible outcomes. Rationale: recovery mechanics can improve without changing settings outcomes the user observes. The implemented rules (SET-1 to SET-9) are in `settings-and-startup-differences.md`: corrupt and unreadable files are preserved and reported, schema version 2 with a new `settings.json.v1.<id>.bak` backup that never overwrites an existing one and read-only newer schemas, lexical path validation, an 8 MiB limit, returned save errors, case-folding approximations, clamped sidebar values, the supported `file:` URI forms, the 8.3 short-name hook (SET-8c), and the search-state API shape. The v1 settings fixtures match exactly.
* **Sanitizer differences (SAN-1 to SAN-11) — proposed.** See `sanitizer-ammonia-differences.md`: CSS normalization, stricter URL policy with .NET-style remote-image blanking, inline-only SVG, 128 MiB limits with nesting/work/reparent/attribute budgets that fail closed, chunked parallel cleaning with byte-identical output, a Marknexia-owned linear serializer (needs `--cfg ammonia_unstable`), white-space-only input, the `<pre>`/`<textarea>` leading line feed, and attacker-controlled attributes the bridge must treat as untrusted.
* **Markdown source diagnostics — proposed.** See `markdown-source-diagnostics.md`: an additive, non-serialized diagnostics field; HTML output and fixtures are unchanged.
* **Markdown resource limits — proposed.** See `markdown-resource-limits.md`: container and inline nesting flattened beyond depth 32, and a rendered-body output cap (default 128 MiB) that fails the parse.
* **Rendering differences (REND-1 to REND-7) — proposed.** See `rendering-differences.md`: the .NET size limits (50 MiB source, 128 MiB page) with the sanitizer's budgets, C#-only highlighting, LF page bytes, single-pass remote-image blanking, math depth clamp, text-handling approximations, and API shape (including cooperative cancellation).
* **Mermaid runtime (MER-1 to MER-5) — proposed.** See `mermaid-runtime.md`: the pinned .NET runtime (Mermaid 10.9.1, CRLF bytes, `packaging/webview/mermaid.lock.json`) served from memory by the resource broker instead of an extracted folder mapping, only to a page whose template loads it, at exactly its URI, with `no-store` headers.
* **Navigation probe order and case folding (NAV-1 to NAV-4) — proposed.** See `navigation-probe-order.md`:
  * A relative escape is rejected before the current-file probe.
  * `..` above the drive root is rejected rather than clamped.
  * A drive-root current file is rejected.
  * Containment folds ASCII case only, so non-ASCII case variants are false blocks.

  The file also sets native-adapter requirements: replace the virtual file lookup, and check containment on the final path of the opened handle. The positive navigation fixtures match .NET exactly.
* **Repository scan (RS-1 to RS-6) — proposed.** See `repository-scan.md`: scan limits (depth 64, 100,000 files, 1,000,000 entries, 64 MiB of kept path text) with a partial tree and a limits flag (paths over the 32 KiB gate limit are reported too), roots and entry names held to the document path gate (drive and UNC share), non-ASCII case folding from the Rust Unicode tables, and fail-soft access-denied handling in root detection (other errors are returned). Filters, ignored folders, hidden and reparse-point rules, pruning and order match .NET.
* **Shell chrome (CHROME-1 to CHROME-15) — proposed.** See `shell-chrome-differences.md`: recent files as a sidebar view, toolbar, menu and row-button gaps, back/forward by scrolling, message-box dialogs, no `crash.log` line, remote images still denied by the broker, keyboard sidebar resize, tab reuse only from sidebar paths, the `MARKNEXIA_SETTINGS_PATH` override, 44-DIP exceptions, Tab traversal, active-tab-only reloads, controller re-creation on reload, and gated, off-thread path checks.
* **WebView2 missing runtime (WV2-1 to WV2-9) — proposed.** See `webview2-missing-runtime.md`: startup detection with a missing-runtime state in the document area and the diagnostics bar, an `Install WebView2 Runtime` action that runs only on user request (bounded HTTPS download from Microsoft, Authenticode and Microsoft-signer check, non-elevated run, one detection), failures that keep the shell usable with Microsoft's offline installer link and no automatic retry, and a live session start after a successful install.
* **Shell input (FIND-1 to FIND-8, DROP-1 to DROP-2, SI-1 to SI-6, TAB-1 to TAB-5, MSG-1, SHUT-1) — proposed.** See `shell-input.md`: F3 and Shift+F3, find chords leaving the document, a 1,024-unit query limit, strict typed find messages through a host-injected adapter (page bytes unchanged), path-gated drops and activations, a same-user, same-session named-pipe hand-off with sender-relative paths and an independent-instance fallback, an instance-key override for tests, and always-visible tab close buttons with a UIA `Close Tab` Invoke child and live drag reorder.
