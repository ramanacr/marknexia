# Repository scan and tree differences

Status: **proposed — requires Task 8 approval**

Scope: `crates/marknexia-files/src/repository.rs` and `GatedPath` in `crates/marknexia-files/src/path.rs`. The .NET baseline is `src/Marknexia.Files/RepositoryService.cs` and `src/Marknexia.Files/RepositoryTreeBuilder.cs`.

## What is the same as .NET

The tests in `crates/marknexia-files/tests/repository_scan.rs` check these rules on temporary folders:

* The extension sets: `.md`, `.markdown`, `.mdown`, `.mkdn`, `.png`, `.jpg`, `.jpeg`, `.gif`, `.svg`, `.webp`, `.ico`, `.bmp`, `.pdf`. The match ignores case. The extension is found like `Path.GetExtension`, so a file named `.md` is listed and `a.md.` is not.
* The ignored folders. The tree ignores 13 names, and workspace enumeration ignores 7 names. Both lists are the .NET lists, and the match ignores case.
* Hidden entries. The tree always skips them. Workspace enumeration skips them unless `show_hidden` is set. A dot folder such as `.github` is not hidden on Windows.
* Reparse points. Junctions, symbolic links, mount points and other reparse points are never listed and never entered, as in .NET. A junction that leads out of the root or back into the root is skipped. A root that is itself a junction is scanned, as in .NET.
* The tree order. Folders come first. Then names sort by `StringComparer.OrdinalIgnoreCase` (uppercase forms, so `_` sorts after letters). The sort is stable, so two names that are equal when case is ignored keep the listing order.
* Empty folders. A folder without supported files is left out of the tree. The root is always present.
* A missing root, or a root that is a file, gives an empty root node.
* An access-denied folder gives an empty listing. Any other read error fails the whole scan. In .NET this error is an `IOException`, and the window shows "The repository tree could not be loaded."
* Root detection checks `.git` (a folder or a file), `*.sln` and `*.slnx`, from the file's folder upwards. `create_context` sets the repository kind from `.git`.
* UNC share roots (`\\server\share\...` and `\\?\UNC\server\share\...`) are allowed (owner decision).

## Observable differences

| ID | Case | .NET | Rust |
| --- | --- | --- | --- |
| RS-1 | Size of the scan | No limits. The recursive walk can overflow the stack on a very deep tree, which ends the process. | `ScanLimits` sets five limits. `max_depth` is 64 folder levels by default, with a hard ceiling of 256. `max_files` is 100,000 files. `max_entries` is 1,000,000 directory entries read. `max_path_bytes` is 64 MiB of path text kept (result file paths, names of folders waiting to be visited, paths of entered folders). The 32 KiB gate limit on one path is described in RS-3. The walk is iterative. Each entry is classified (folder, supported file or skipped) before its path is built. Unsupported files keep nothing, and a pending folder keeps only its name. When a limit is reached, the scan returns the partial tree, and `LimitsHit` shows which limit was reached. `LimitsHit::depth` means that a folder at the depth limit had subfolders that were not entered. Those subfolders may hold no supported files, so the result *may* be incomplete. When `LimitsHit::any()` is true, the shell must tell the user that the tree may be incomplete. |
| RS-2 | Root forms | `CanonicalizePath` accepts relative paths (resolved against the current folder), `file://` URIs and device paths. An unusable root gives an empty node. | The root must be an absolute drive path (`C:\...`, `\\?\C:\...`) or a UNC share path (`\\server\share\...`, `\\?\UNC\server\share\...`) that passes `GatedPath`. Refused roots: (1) a path longer than 32 KiB in UTF-8; (2) a `.` or `..` component in any form, which also refuses `\\.\` device paths; (3) other `\\?\` forms (GLOBALROOT, volume GUIDs, devices); (4) a `/` in a verbatim `\\?\` root; (5) a UNC path without both a server and a share name; (6) a server or share name that is empty, holds a non-ASCII character, a control character or one of `:` `<` `>` `"` `|` `?` `*`, or ends with `.` or a space; (7) a server name with `@` (`@SSL`, `@port`); (8) the `pipe`, `mailslot`, `IPC$` and `DavWWWRoot` shares, also with trailing dots or spaces; (9) below the volume, a component with `:` `<` `>` `"` `|` `?` `*` or a control character, a reserved device name (`CON`, `PRN`, `AUX`, `NUL`, `CONIN$`, `CONOUT$`, `COM0`-`COM9`, `LPT0`-`LPT9` and the superscript-digit forms, with any extension) or a name that ends with `.` or a space; (10) a relative path. `build_repository_tree` and `enumerate_workspace_files` return `ScanError::InvalidRoot`. `detect_repository_root` returns `Ok(None)` and `create_context` returns `None`. The shell converts `file://` arguments before it calls the scan. |
| RS-3 | Entries that the document gate refuses | Listed. | Skipped: the gate in RS-2 (9) is applied to each full child path. This covers reserved device names (`CON.md`, `nul.png`), names that end with `.` or a space, and names that are not valid UTF-16 (an unpaired surrogate). A refused folder is not entered, so its whole subtree is left out. Such names exist only when another program creates them with `\\?\` paths, and the Rust document open refuses them anyway. A child path longer than the gate's 32 KiB (UTF-8) limit is also skipped, but it sets `LimitsHit::path_length`, so the shell can report it. |
| RS-4 | Non-ASCII case folding for sort and match | The .NET ordinal casing table. | Simple uppercase mapping from the Rust standard library's Unicode tables. A character with a multi-character uppercase form (`ß`) stays as it is. U+0131 (dotless i) stays as it is, as in .NET. ASCII names give the same result. Names with case pairs that are in one Unicode version and not in the other can sort differently. Not verified: Rust folds U+017F (long s, `ſ`) to `S`. If .NET ordinal casing keeps U+017F unchanged, a folder such as `Teſtreſults` is ignored in Rust and listed in .NET, and an extension such as `.ſvg` is listed in Rust and skipped in .NET. The same rule is used for the ignored-folder names and the extensions. |
| RS-5 | Errors during root detection | `Directory.EnumerateFiles` throws for any listing error, including `UnauthorizedAccessException`, and `DetectRepositoryRoot` fails. | `detect_repository_root` returns `Result<Option<PathBuf>, ScanError>`. When listing a folder for `*.sln` / `*.slnx` is denied (at the start or part-way through), that folder has no solution marker, and the search continues upwards. This is the difference. Any other listing error returns `ScanError::Io`, as .NET throws it. The `.git` check uses file metadata and treats any error as "no marker", as `Directory.Exists` and `File.Exists` do. The `*.sln` check reads at most 1,000,000 entries in each folder. |
| RS-6 | Access denied part-way through a workspace folder | The files added before the exception stay in the result. | The folder contributes no entries. Windows reports access denied when the listing starts, so this case is not expected in practice. |

Cancellation is not a difference. .NET throws `OperationCanceledException`, and the Rust scan returns `ScanError::Cancelled`. In both, the partial tree is dropped (design spec §10, "Cancelled scan: Discard partial results"). Rust checks the `cancel` callback before each directory entry and before each folder.

## Residual risk (same as .NET)

The reparse-point check uses the attributes from the directory listing. Then the scan opens the subfolder by path. If another process replaces a listed folder with a junction between these two steps, Windows follows the junction. .NET has the same race. The process that does this needs write access inside the repository, and the scan returns only names and paths. When a listed document is opened, `read_source` checks the final path of the opened handle with the same gate. That check does not check repository containment. To close the race, a later native adapter must list each folder through a handle opened with `FILE_FLAG_OPEN_REPARSE_POINT`, for example with `GetFileInformationByHandleEx`. This needs `unsafe` code, so it belongs in `marknexia-win32`, not in `marknexia-files`.

## Unverified assumption

The tree root's display name for a UNC share root (`\\server\share`) is the whole root text in Rust. This copies .NET `DirectoryInfo.Name` for a root. A .NET run has not checked this value.
