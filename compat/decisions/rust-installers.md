# Rust preview installers: per-user setup and MSIX (unsigned, CI only)

Status: **approved — owner decision 2026-11-07**

Scope: `crates/marknexia-setup` (all of it), `packaging/rust-msix/AppxManifest.xml`, `scripts/New-RustInstallerPackages.ps1`, `scripts/Test-RustSetupPayload.ps1`, `scripts/Test-RustSetupInstall.ps1`, the optional naming parameters of `scripts/Generate-RustSbom.ps1` and `scripts/Test-RustSbom.ps1`, `tests/perf/rust_setup_payload.tests.ps1`, and the setup and MSIX steps of the `rust-release-build` job in `.github/workflows/rust-feasibility.yml`. The .NET sources are `src/Marknexia.Setup/Program.cs`, `src/Marknexia.App/Package.appxmanifest` and `scripts/Test-MsixPackage.ps1`; they are not changed. Owner decision 2026-11-07: build an unsigned per-user setup and an MSIX for x64 and ARM64 in CI only, and upload them only as workflow artifacts (no signing, no release, no publishing).

Evidence class: implemented, compiled and headless-tested. 50 unit tests in `crates/marknexia-setup` use an in-memory registry (`MemoryRegistry`), a fake shell, temp folders and text payloads under non-executable stand-in names (`FileNames::stand_ins`, for example `shell.bin.txt`; the real `.exe` and `.dll` names exist only in memory and in CI): no test writes the real registry, executable bytes or a file named `*.exe` or `*.dll` (`tests/perf/no_synthetic_pe_disk.tests.ps1` enforces the last point), and `cargo test` never links the installer (`test = false`, no integration tests). `tests/perf/rust_setup_payload.tests.ps1` checks the independent payload parser with text-only containers and the CI-only guards. **Not yet run (CI only):** the two reproducible setup builds with the embedded payload, the payload check of the built executable, the setup and MSIX SBOM validation, `makeappx pack` and `unpack`, and the x64 silent install, upgrade and uninstall round trip. **Never run:** the ARM64 setup (the release-build job runs on x64), an MSIX install (`Add-AppxPackage -AllowUnsigned` was not tried), and any interactive setup dialog.

## .NET behavior (read from the source, not observed)

`MarknexiaSetup.exe` installs to `%LOCALAPPDATA%\Programs\Marknexia` (or `--dir`), with an embedded ZIP that must not contain traversal entries and must contain six named files. It stages into `<dir>.staging-<guid>`, moves an existing install to `<dir>.backup-<guid>`, swaps, and deletes the backup; a running `Marknexia.App` stops the install. It always registers `Marknexia.MarkdownFile` as the **default** for `.md`, `.markdown`, `.mdown` and `.mkdn` (it writes each extension's default value, `PerceivedType`, a preview handler, `OpenWithProgids`, `OpenWithList` and `Applications\Marknexia.App.exe`), a Start menu folder `Marknexia` with `Marknexia.lnk`, and the HKCU uninstall key `Marknexia` with `UninstallString` and `QuietUninstallString`. Uninstall deletes the registrations and the whole install folder, using a hidden PowerShell script when it runs from that folder. The MSIX identity is `RRCLabs.Marknexia` with a `markdown` file type association.

## Observable differences

| ID | Condition | .NET oracle | Rust preview |
| --- | --- | --- | --- |
| RINST-1 | Identity and location | `Marknexia`: folder `%LOCALAPPDATA%\Programs\Marknexia`, uninstall key `Marknexia`, ProgID `Marknexia.MarkdownFile`, Start menu `Programs\Marknexia\Marknexia.lnk`, `MarknexiaSetup.exe`. | Every name differs, so both editions install side by side: folder `%LOCALAPPDATA%\Programs\Marknexia Rust Preview`, uninstall key `MarknexiaRustPreview` (display name `Marknexia (Rust preview)`), ProgID `Marknexia.RustPreview.MarkdownFile`, shortcut `Programs\Marknexia (Rust preview).lnk`, uninstaller `marknexia-rust-preview-setup.exe`. Tests assert that no .NET name is used and that .NET keys survive install and uninstall. |
| RINST-2 | File associations | Always; takes the default for the four extensions. | **Opt-in.** Interactive setup asks a separate question with **No** as the default; `--silent` adds them only with `--associate`. Even then the preview writes only its ProgID, `Applications\marknexia-win32.exe`, the extensions' `OpenWithProgids` entries and Default Apps capabilities (`Software\Marknexia\RustPreview\Capabilities`, `RegisteredApplications`). It never writes an extension's default value, `PerceivedType`, a preview handler or `UserChoice`, so the current default (for example the .NET edition) stays until the user changes it in Settings. An upgrade keeps an earlier opt-in; `--no-associate` removes it. Uninstall removes the `Applications` entry only when its command opens this installation (Windows writes the same key for a portable copy chosen with "Open with"). |
| RINST-3 | Payload | Embedded ZIP; traversal, size and required-file checks; no hash. | Embedded container `MNXSETUP-PAYLD-1` (`src/container.rs`) with exactly `README.txt`, `THIRD-PARTY-NOTICES.txt`, `WebView2Loader.dll`, `marknexia-sbom.spdx.json` and `marknexia-win32.exe`. Before it asks or writes anything, setup checks the SHA-256 of the whole container and of every file, the exact file set, the name rules and the limits (16 files, 64 MiB). A developer build has no payload and refuses (`This setup executable does not contain an application payload.`). Files are created new and read back and hashed after writing. The hashes give integrity, not authenticity: the executable is unsigned (RINST-14). |
| RINST-4 | Install transaction | Staging, backup and swap; a running app stops the install. | The same staging, backup and swap, plus: a running installed shell **or** a running payload that the updater staged in `Updates\versions` stops the install before anything is written (`Close Marknexia (Rust preview) before installing or upgrading it.`); leftover `.staging-*` and `.backup-*` folders of this edition are removed first; a failed registration restores the previous files (or, for a first install, removes the new files, keys and shortcut). |
| RINST-5 | Uninstall | Deletes the whole install folder; a hidden PowerShell script deletes it when setup runs from there. | No PowerShell. Setup removes only the files it installed, then the folder when it is empty; any other file (for example a user's note) and the folder are kept and logged. The running uninstaller cannot delete itself, so it renames itself to `%TEMP%\marknexia-rust-preview-uninstall-<token>.exe`; the next setup run or Windows temporary-file cleanup removes that copy. A running shell stops the uninstall before anything is removed. Uninstall is safe to repeat. |
| RINST-6 | Updater pointer model | The .NET updater copies over the install folder. | Install never touches `%LOCALAPPDATA%\Marknexia\Updates`. The install folder is the "unpacked installation" of UPD-11, which the updater never changes; the installed shell forwards to a staged payload only when `active.json` names a newer version (UPD-12). A newer setup therefore wins over an older pointer, and an updated installation keeps working. Uninstall removes only the Rust updater's names (`active.json`, `transaction.json`, `highest-seen.json`, `last-update-failure.json`, `versions\<version>-<arch>`, `staging\pending-*`, `health\ack-*.json`, and the emptied folders), never follows a reparse point, and keeps the .NET updater's `pending-<guid>` folders and every other entry. **Note:** a portable ZIP copy of the same user shares this folder; after an uninstall it runs its own executable until it updates again. |
| RINST-7 | Settings | Not touched by setup. | Not written by setup either. Setup reads `%LOCALAPPDATA%\Marknexia\settings.json` read-only with the shell's parser and logs what the shell will find (missing, schema 1 that the shell backs up before its first change, newer schema read-only, or invalid). Migration stays in the shell's `SettingsStore` (SET rules). Uninstall keeps `settings.json` and `%LOCALAPPDATA%\Marknexia\WebView2`, which both editions use. |
| RINST-8 | Elevation | No manifest entry for elevation (.NET apphost). | The setup embeds an `asInvoker` manifest (`/MANIFESTUAC`), writes only `HKEY_CURRENT_USER` and the user's folders, and never asks for elevation. As in .NET, an elevated run installs for the elevated account. |
| RINST-9 | Command line | `--install`, `--uninstall`, `--verify`, `--silent`, `--dir`, `--architecture`, `--scope`, slash forms. | `--install` (default), `--uninstall`, `--verify [--report <file>]`, `--silent`, `--associate`, `--no-associate`, `--log <file>`, `--help`. No `--dir` (one fixed per-user location, also for uninstall), no `--scope` and no `--architecture` (each build holds one architecture). Exit codes: 0 success, 1 failure, 2 usage, 3 cancelled. |
| RINST-10 | WebView2 runtime | Not checked. | Detected read-only (EdgeUpdate `pv` in HKLM and HKCU) and logged; when it is missing, the interactive success message says that the shell offers the install when it starts (WV2-2, WV2-3). The runtime is never bundled (design section 14). |
| RINST-11 | MSIX | `RRCLabs.Marknexia`, Store publisher, `markdown` association. | `Marknexia.RustPreview`, display name `Marknexia (Rust preview)`, version `<x.y.z>.0`, `ProcessorArchitecture` x64 or arm64, publisher `CN=Marknexia Rust Preview UNSIGNED, OID.2.25.311729368913984317654407730594956997722=1` (the unsigned-package marker), application `MarknexiaRustPreview` running `marknexia-win32.exe` with `runFullTrust`, and a `markdown-rust-preview` association that only adds an "Open with" entry. Unsigned: no test certificate is created, so the package can be added only with `Add-AppxPackage -AllowUnsigned` (not verified). "Check for updates" is grayed in a packaged process (UPD-3). **Unverified risk:** a packaged process may have its `%LOCALAPPDATA%` writes redirected to the package's private folder, so the MSIX shell may not share `settings.json` with the .NET edition. |
| RINST-12 | SBOM | One SPDX file in the payload (`marknexia-sbom.spdx.json`). | Each artifact has its own SPDX 2.3 SBOM (same generator and crate graph as the ZIP; the distribution package names the setup or the MSIX). It is embedded as `marknexia-sbom.spdx.json` and uploaded next to the artifact. CI validates it against the files extracted from the built artifact (`Test-RustSbom.ps1`) and with `pyspdxtools`. **Gaps:** the setup program's own crate `marknexia-setup` is not listed (CI checks that every other crate it links is listed); the MSIX logos and `AppxManifest.xml` (first-party) are not in the file inventory. Proposal: a second root package in the generator. |
| RINST-13 | Reproducibility and size | Not checked. | The setup is built twice from clean checkouts and must be byte-identical. The MSIX is not checked for reproducibility. The setup size is recorded against the Phase 7 limit (15 MB) but does not fail the build. |
| RINST-14 | Signing and release | Signed releases. | Nothing is signed, attached to a release or published. Artifacts are `marknexia-rust-UNSIGNED-PREVIEW-setup-<target>` and `marknexia-rust-UNSIGNED-PREVIEW-msix-<target>` (14 days), skipped for pull requests from forks. SmartScreen and antivirus products can warn about the unsigned setup. |

## Only CI can verify

1. That `cargo build -p marknexia-setup` with `MARKNEXIA_SETUP_PAYLOAD_DIR` links, is reproducible, and has the right PE machine, for x64 and ARM64.
2. That the built setup holds exactly one valid container with the five expected files (`Test-RustSetupPayload.ps1`), and that the extracted files match the SBOM.
3. That `makeappx pack` accepts the manifest and `makeappx unpack` returns exactly the staged files.
4. On x64 only: the real HKCU adapter, the `IShellLinkW` shortcut, the self-move of the running uninstaller, and the full install, upgrade and uninstall round trip (`Test-RustSetupInstall.ps1`).
5. Not covered by CI either: the interactive dialogs, the ARM64 setup run, an MSIX install, SmartScreen behavior, and coexistence with a real .NET installation (needs a manual or clean-VM run).

## Rollback

Remove the setup and MSIX steps and their two uploads from `rust-release-build`, and the `crates/marknexia-setup` workspace member. The portable ZIP and its SBOM are unchanged (the new SBOM script parameters default to the ZIP's wording). An installed preview is removed with its own uninstaller (`--uninstall --silent`).
