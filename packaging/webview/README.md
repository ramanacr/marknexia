# WebView2 loader and Evergreen contract

The Rust/Win32 package carries exactly one native `WebView2Loader.dll`, matching the package PE architecture. `loader.lock.json` pins Microsoft's `Microsoft.Web.WebView2` NuGet package, its SHA-256, and the SHA-256 and byte length of each selected loader entry. `Stage-WebView2Loader.ps1` rejects package or entry hash drift and checks the PE machine before moving the selected loader into release staging. A caller's architecture label is not evidence. Do not ship the other architecture's loader, managed WebView2 assemblies, a fixed runtime, or Chromium.

At startup the native adapter calls `GetAvailableCoreWebView2BrowserVersionString` with the default browser executable folder and treats a null or empty result as Evergreen unavailable. The Win32 shell remains usable and renders a clear missing-runtime state. Installation is offered only after an explicit user action. The online path downloads Microsoft's current Evergreen bootstrapper over HTTPS, verifies its Microsoft Authenticode signature, then runs it without elevation by default and retries runtime detection. Offline, failed download, failed signature, installation cancellation, and failed installation keep the shell usable and show a link to Microsoft's official offline Evergreen installer; they do not trigger an automatic retry loop. The bootstrapper is an on-demand dependency, excluded from installer size. Production creation uses the shared Evergreen Runtime and does not request a preview Edge channel.

This is the distribution decision, not native runtime proof. The adapter, missing-runtime UI, user-initiated bootstrap, offline failure, and ARM64 behavior require native tests in Tasks 5–6 and the Task 8 gate. Microsoft documents the [Evergreen deployment and loader requirements](https://learn.microsoft.com/en-us/microsoft-edge/webview2/concepts/distribution); the pinned SDK package is [Microsoft.Web.WebView2 1.0.4191.47](https://www.nuget.org/packages/Microsoft.Web.WebView2/1.0.4191.47).
